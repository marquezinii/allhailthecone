# Security policy

## Scope

Report vulnerabilities affecting this repository, its build process, the deployed archive or checked-in configuration. Examples include exposure of credentials, an unsafe dependency path, content-security-policy regressions or a way to alter published material without authorization.

Creative disagreements, canon proposals and ordinary page defects belong in [Discussions](https://github.com/marquezinii/allhailthecone/discussions) or an issue, not a security report.

## Report privately

Use [GitHub private vulnerability reporting](https://github.com/marquezinii/allhailthecone/security/advisories/new). Do not publish exploit details, tokens, personal data or sensitive reproduction steps in a public issue, discussion or Discord message.

Include the affected URL or file, a minimal reproduction, practical impact and any safe mitigation you have identified. Keep testing limited to this project and avoid accessing or changing other people's data.

## What happens next

Maintainers will review reports in good faith, confirm the affected scope where possible and coordinate a fix before public disclosure. Acknowledgement or a release date is not guaranteed, but reports that include clear reproduction details are easier to resolve responsibly.
